# 수업 웹 아카이브 — 운영 가이드

> 학생 웹 작업물을 학기마다 장기 보존하기 위한 도구의 설계와 운영 매뉴얼.
> 핵심 방향: 특정 서비스가 아니라 **WARC/WACZ 표준 포맷 + 서버 없는 재생 + 자족적 폴더 + 복제 백업**에 의존한다.
> 개정 기준일: 2026년 7월 (자족적 폴더 방식으로 단순화)

---

## 0. 한눈에 보기 (TL;DR)

매 학기 약 30명의 학생 웹사이트를 캡처해, **폴더 하나에 다 담아 두는** 아카이브 도구다. 설계 원칙은 단 하나 — **"10~20년 뒤에도 열 수 있는 것만 쓴다."** 그래서 빠르게 바뀌는 프레임워크나 특정 회사 서비스에 의존하지 않는다.

핵심 결정(2026-07): **온라인 사이트·자동화·클라우드를 걷어내고, 자족적 폴더 하나로 만든다.** 이 폴더 안에 목록 페이지, 명단, 아카이브 파일, 재생기가 다 들어 있어 USB나 드라이브에 복사만 해도 보존된다. 역할은 **구글 시트 = 접수함(이름·수업·링크만), manifest.csv = 관리 원본(그 외 전부)**으로 나눈다. 보는 시점에는 구글에 의존하지 않으므로 시트가 사라져도 아카이브는 멀쩡하다.

| 역할 | 선택한 기술 | 왜 오래 가는가 |
|---|---|---|
| 캡처 | **Playwright(실제 Chromium)** | 자바스크립트 사이트도 충실히 캡처. Docker 불필요. 도구가 낡아도 결과물(WACZ)은 그대로 유효 |
| 보존 포맷 | **WACZ (WARC 기반)** | WARC는 ISO 28500 국제표준. 도서관·국가기록원이 쓰는 포맷 |
| 재생 | **replayweb.page** | 서버 없이 정적 파일(js)만으로 재생. 폴더에 벤더링(자가호스팅) |
| 접수·관리 | **구글 시트(접수) → manifest.csv(관리)** | 링크 수집은 시트, 관리는 사람이 읽는 CSV로 |
| 저장/배포 | **자족적 폴더 (USB·드라이브)** | 외부 서비스 0개. 복사가 곧 백업 |

> **맥락**: 교수님이 언급하신 **Rhizome의 Conifer**는 중요한 선례다. 이 설계는 Conifer 같은 특정 호스팅 서비스에 의존하지 않고, Webrecorder 생태계의 개방형 포맷·도구(**WACZ/WARC + replayweb.page**)를 조합해 수업 자체의 장기 아카이브를 만든다. **Conifer의 정신은 잇되, 더 오래 옮겨 다닐 수 있는 방식**이다.

## 1. 배경과 요구사항

학생들의 Git 레포지토리나 개인 사이트는 언젠가 사라진다(졸업, 호스팅 만료, 플랫폼 폐업). 그래서 **"지금 살아있는 모습 그대로"를 박제**하는 것이 목표다.

- 규모: 학기당 약 30명, 매 학기/매년 반복, **10~20년 지속 가능하고 옮길 수 있는 구조**
- 입력: 학생 웹사이트 링크
- 결과물: 캡처된 작품을 모아 보여주는 아카이브(폴더)
- 제약: **최소 10년 유지·이전 가능한 기술만**. 최신·급변 기술 배제
- 운영: **단순함 최우선.** 자동화보다 "고장 날 것이 없는" 구조

## 2. 왜 이 스택인가 — 오래 가는 설계의 원칙

웹 아카이빙은 도서관·기록학계가 수십 년 다듬어 온 분야다. 그 디지털 보존 원칙을 빌리면 답은 거의 정해져 있다.

**원칙 1 — 개방형 표준 포맷만.** 독점 포맷은 회사가 사라지면 같이 죽는다. **WARC**는 ISO 28500 국제표준이고, **WACZ**는 그 WARC에 색인을 곁들여 ZIP으로 묶은 것뿐이다. ZIP과 WARC는 수십 년이 지나도 열 수 있다.

**원칙 2 — 서버 없이(서버리스).** 데이터베이스·백엔드·로그인은 전부 "관리해야 살아있는" 것이다. **replayweb.page**는 서버가 필요 없다. 브라우저 안 Service Worker가 WACZ를 직접 읽어 재생하므로 정적 파일만 있으면 된다.

**원칙 3 — 프레임워크 churn 회피.** React/Next는 훌륭하지만 1~2년마다 호환성이 깨진다. 그래서 목록 페이지는 **순수 HTML + 바닐라 JS**로 만든다. 빌드 단계가 없으면 썩을 것도 없다.

**원칙 4 — 사람이 읽는 명단.** 누가 무엇을 언제 캡처했는지는 **CSV 텍스트 파일**로 관리한다. 10년 뒤 도구가 다 바뀌어도 메모장으로 열어 이해할 수 있다.

**원칙 5 — 복제가 곧 보존이다(LOCKSS).** *Lots Of Copies Keep Stuff Safe.* 한 곳에만 있으면 그 한 곳이 사라질 때 끝이다. 폴더를 USB·드라이브 등 여러 곳에 복제한다(7장).

**원칙 6 — 도구와 자산을 분리한다.** 캡처 도구(Playwright)는 빠르게 변하는 소모품이지만, 그 결과물(WACZ)은 표준이라 안 변한다. 도구가 5년 뒤 낡아도 그때 최신 도구로 다시 캡처하면 되고, **이미 만든 WACZ는 영원히 유효**하다.

**피해야 할 안티패턴**: 커스텀 백엔드, SQL에 아카이브 저장, SPA 뷰어, 특정 클라우드 독점 기능 의존, 스크린샷 PDF만 남기기(인터랙션·링크가 다 죽음). 이 설계는 이 모두를 배제한다.

## 3. 전체 구조

```
 ┌───────────────────────────────────────────────────────────┐
 │  구글 시트 "manifest"  (접수함 — 이름·수업·링크만)          │
 │   student_name · title · original_url · semester · status  │
 └───────────────────────────┬───────────────────────────────┘
                             │  캡처.command 가 CSV로 내려받음
                             ▼
 ┌───────────────────────────────────────────────────────────┐
 │  아카이브 폴더  (이 폴더가 곧 아카이브 — USB/드라이브 보관) │
 │                                                            │
 │   manifest.csv ──► 캡처.command ──► Playwright 캡처         │
 │   (관리 원본)         (더블클릭)      ▼                     │
 │                                    wacz/<학기>/작품.wacz    │
 │                                                            │
 │   보기.command ──► 로컬 서버 ──► index.html (목록)          │
 │   (더블클릭)                     └► viewer.html (재생)      │
 │                                     └► replay/ (재생기)     │
 └───────────────────────────────────────────────────────────┘
```

말로 풀면: **구글 시트에 학생·URL 한 줄을 추가**하고 → **캡처.command를 더블클릭**하면 시트를 내려받아 대기 중인 사이트를 통째로 캡처(WACZ)해 폴더에 넣는다 → **보기.command를 더블클릭**하면 로컬 서버가 뜨고 브라우저에서 목록을 보고, 작품을 누르면 캡처된 그 시점의 사이트가 그대로 재생된다. 이 모든 게 인터넷 서비스 없이 폴더 안에서 끝난다.

## 5. 평소 운영 — 3단계

### 1단계. 접수 (구글 시트 = 접수함)

[manifest 시트](https://docs.google.com/spreadsheets/d/1ttG_2q0ZKYopjJmkPUF9S3d3azgE8ymeFPboMheGVig/edit)에 새 학생을 한 줄 추가한다. 시트에는 **접수 3칸만** 넣는다(학생이 직접 채우게 해도 된다).

| 칸 | 예시 | 설명 |
|---|---|---|
| `student_name` | Jane Doe | 학생 이름/표기명 |
| `semester` | 2027-spring | 학기(또는 수업) 구분 |
| `original_url` | https://jane.github.io/proj/ | 로그인 없이 열리는 공개 URL |

`캡처.command`가 **시트의 새 학생만** manifest.csv로 가져와 `pending`으로 넣는다. 이미 있는 학생의 관리 데이터(상태·메모·캡처 결과)는 절대 건드리지 않는다. 그 외 모든 관리는 2·3단계 이후 **manifest.csv에서** 한다(9장).

> `semester`가 학기/수업 구분이다. **새 수업이 추가돼도 새 `semester` 이름만 적으면** 된다 — 폴더는 캡처할 때 자동 생성된다.
>
> 시트에 다른 칸(제목·상태 등)이 있어도 무시되므로 남겨 둬도 되지만, 헷갈리지 않으려면 **이름·수업·링크 세 칸만** 두는 것을 권한다.

### 2단계. 캡처 (`캡처.command` 더블클릭)

더블클릭하면 알아서 진행합니다. 사용자는 엔터만 누르면 됩니다.

1. (처음 한 번만) 캡처 도구가 없으면 **설치할지 물어보고 자동 설치**한다.
2. 구글 시트(접수함)의 **새 학생만** manifest.csv로 가져온다(기존 관리 데이터는 그대로).
3. **아직 캡처 안 된 작품 목록**(대기·재캡처 대상)을 보여준다. 없으면 "캡처할 작품이 없습니다"로 끝난다.
4. **엔터 한 번**이면 캡처를 시작한다. 끝나면 각 행이 `status=ok`가 되고 `wacz_file`·`archived_date`·`sha256`이 자동으로 채워진다.

Docker도, 로그인도, GitHub 토큰도 필요 없다. **특정 학생을 다시 캡처**하려면 manifest.csv에서 그 학생 `status`를 `recapture-needed`로 바꾸고 다시 실행하면 그 학생이 목록에 잡힌다.

### 3단계. 보기 (`보기.command` 더블클릭)

로컬 서버를 띄우고 브라우저로 목록을 연다. 작품의 **Archive** 버튼을 누르면 보존된 사이트가 그대로 재생된다. 검색·학기 필터가 있다. 운영 현황(대기·비공개 포함)은 `admin.html`에서 본다.

> ⚠️ **`index.html`을 직접 더블클릭하지 말 것.** WACZ 재생은 Service Worker를 쓰는데, 이건 `file://`(파일 직접 열기)에서는 동작하지 않는다. 반드시 **보기.command**로 로컬 서버를 통해 열어야 재생된다. macOS에 내장된 파이썬만 있으면 되므로 보기에는 별도 설치가 필요 없다.

## 6. 최초 1회 준비 (캡처하는 Mac에서만)

캡처에는 파이썬 도구가 필요하다. 한 번만 설치한다.

```bash
python3 -m pip install playwright warcio wacz
python3 -m playwright install chromium
```

- **보기**만 할 사람은 이 설치가 필요 없다(내장 파이썬으로 충분).
- 처음 `.command`를 더블클릭하면 "확인되지 않은 개발자" 경고가 뜰 수 있다. 파일을 **우클릭 → 열기**를 한 번만 하면 이후로는 그냥 더블클릭된다.
- 캡처가 약한 인터랙티브 작품은 [ArchiveWeb.page](https://webrecorder.net/archivewebpage)로 사람이 직접 클릭하며 녹화해, 파일명을 `slug(이름)-slug(학기).wacz` 규칙에 맞춰 `wacz/<학기>/`에 넣어도 된다(결과물이 같은 WACZ라 그대로 재생된다).

## 7. 학기별 운영 루틴 (체크리스트)

매 학기 말 반복하는 일은 이게 전부다.

- [ ] 학생 공개 URL 수집(**사이트가 살아있을 때** 마감 공지 — 내려간 뒤엔 못 잡는다)
- [ ] 구글 시트(접수함)에 그 학기 학생 추가 — 이름·수업·링크만(학기 태그 통일: 예 `2026-spring`)
- [ ] `캡처.command` 더블클릭 → 캡처
- [ ] `보기.command`로 각 작품이 제대로 재생되는지 점검(특히 인터랙션 많은 것)
- [ ] 재생이 부실하면 시트에서 `status`를 `recapture-needed`로 바꾸고 다시 캡처
- [ ] 그 학기 결과가 반영된 **폴더를 USB/드라이브에 복사**해 백업(8장)

## 8. 백업과 평생 보존

저장 매체가 이 폴더 하나이므로, **복제**가 곧 보존이다.

**3-2-1 백업.** 폴더를 최소 3벌, 2종류 매체, 1벌은 외부에 둔다. 실무적으로 (1) 작업용 Mac, (2) 외장 USB/SSD, (3) 클라우드 드라이브(구글 드라이브 등) 정도면 충분하다. WACZ는 자족적 파일이라 **폴더를 통째로 복사**하기만 하면 된다.

**정기 무결성(fixity) 점검.** 각 WACZ의 SHA-256이 `manifest.csv`에 기록되어 있다. 1년에 한 번 파일이 손상되지 않았는지(같은 해시인지) 확인하고, 달라지면 백업본과 비교한다.

**포맷 마이그레이션 감시.** WARC/WACZ는 당분간 안전하지만, 디지털 보존은 영원히 "지켜보는" 일이다. 포맷 전환 권고가 나오면 그때 일괄 변환한다. **원본 WARC를 품은 WACZ를 보관**하므로 미래의 어떤 도구로도 다시 처리할 수 있다.

**재생기 노화 대비.** `replay/`(replayweb.page)는 Service Worker 기반이라 먼 미래에 브라우저가 못 돌릴 수 있다. 그때의 보험이 바로 표준 WARC다 — replay가 죽어도 WACZ 안의 WARC를 그 시절 도구(pywb 등)로 다시 열 수 있다. **그러니 재생기보다 원본 WACZ를 잘 보관하는 게 우선이다.**

**제3의 안전망 — Internet Archive(선택).** 정말 영구 보존을 원하면 학생 사이트를 [web.archive.org](https://web.archive.org)의 Save Page Now로도 한 번씩 저장해 둔다. 우리 시스템과 독립적인 또 하나의 사본이 생긴다.

## 9. 상태(status) 값

| status | 의미 | 목록 노출 |
|---|---|---|
| `pending` (또는 빈칸) | 아직 캡처 안 됨 | 대기 목록(admin) |
| `ok` | 캡처 완료 | 공개 (재생 가능) |
| `recapture-needed` | 다시 캡처 필요 | 다음 캡처 대상 |
| `private` / `hidden` | 비공개 | 공개 목록에서 숨김 |

**캡처 성공과 재생 성공은 다르다.** 파일이 만들어져도 핵심 인터랙션이 빠질 수 있으니, 학기 말에는 각 작품을 최소 1회 직접 열어 확인한다. 문제가 있으면 `recapture-needed`로 내려 다시 캡처한다.

검수 체크리스트:
- 시작 페이지가 열린다.
- 주요 링크·버튼·스크롤·인터랙션이 작동한다.
- 이미지·CSS·JS·폰트가 크게 깨지지 않는다.
- 외부 API 의존 기능이 있으면 누락 여부를 `notes`에 기록한다.
- 개인정보·API 키·비공개 토큰·저작권 문제 자료가 노출되지 않는다.

---

## 10. 한계 (정직하게)

**자동 캡처가 약한 케이스.** 로그인이 필요한 페이지, 복잡한 조작에만 반응하는 인터랙티브 아트, 외부 서비스 임베드(유튜브·외부 API)는 일부를 놓칠 수 있다. 이런 작품은 ArchiveWeb.page로 사람이 직접 녹화(예전 Conifer가 하던 방식)해 같은 WACZ로 폴더에 넣으면 된다.

**원본이 사라지기 전에 잡아야 한다.** 아카이브는 캡처 시점의 스냅샷이다. 사이트가 내려간 뒤에는 못 잡으니 **학기 중/직후에 반드시 캡처**한다.

**용량.** 영상·고해상도 에셋이 많으면 WACZ가 커진다(작품당 수십~수백 MB, 구글 슬라이드 등은 100MB 이상도). 학기가 쌓이면 폴더가 커지므로 백업 매체 용량을 넉넉히 준비한다.

**보기에 로컬 서버가 필요하다.** Service Worker 제약상 파일을 직접 열면 재생이 안 되므로 항상 보기.command로 연다. 대신 이건 macOS 내장 파이썬만으로 되므로 추가 설치는 없다.

## 11. 학생 제출 가이드

아카이브 품질은 제출 방식에 크게 좌우된다. 학생에게 미리 안내한다.

- 작품 URL은 로그인 없이 접근 가능해야 한다.
- 마감 이후 최소 2주 이상 사이트를 공개 상태로 유지한다.
- 핵심 이미지·CSS·JS·데이터는 가능하면 같은 도메인/프로젝트 폴더 안에 둔다.
- 외부 API·실시간 서버·유튜브/인스타/드라이브 임베드는 장기 재생에서 깨질 수 있다. 필요하면 대체 설명을 제출한다.
- API 키·비밀번호·개인정보·비공개 토큰을 코드/HTML에 포함하지 않는다.
- 저작권 문제가 있는 이미지·음원·영상 사용 여부를 확인한다.
- 정확한 시작 URL, 작품 제목, 본인 이름/표기명, 공개 동의 여부를 제출한다.

권장 동의 문구:

> 이 프로젝트는 수업 아카이브의 일부로 장기 보존될 수 있습니다. 원본 저장소나 개인 사이트가 삭제되더라도, 제출 시점의 웹사이트 캡처본은 수업 아카이브에 보존될 수 있습니다. 개인정보·비공개 키·저작권 침해 자료를 포함하지 않았음을 확인합니다.

## 12. 인수인계

담당자(교수님/조교)는 바뀐다. 다음 네 가지만 넘기면 5분 만에 이어받는다.

- **(a) 폴더 위치와 백업본 위치** — 원본 폴더가 어디에 있고, 백업 사본(USB/드라이브)이 어디에 있는지.
- **(b) 구글 시트 접근** — [manifest 시트](https://docs.google.com/spreadsheets/d/1ttG_2q0ZKYopjJmkPUF9S3d3azgE8ymeFPboMheGVig/edit)의 편집 권한을 누가 갖는지. 개인 계정보다 수업용 계정 권장.
- **(c) 사용법** — README.md와 이 문서. 실무는 "시트 편집 → 캡처.command → 보기.command" 3단계가 전부.
- **(d) 최초 설치** — 캡처하는 Mac에서 6장의 설치 1회.

시스템이 단순할수록 평생 간다 — 이 설계가 단순한 이유다.

## 부록 B. WACZ 파일명 규칙 (슬러그)

캡처는 `wacz_file`이 비어 있으면 **`slug(student_name)-slug(semester).wacz`**로 이름을 정한다. 슬러그는 소문자화하고 영숫자만 남기며 나머지는 `-`로 바꾼다.

- 예: `Seohyeon Gu` + `2026-spring` → `seohyeon-gu-2026-spring.wacz`
- 목록 페이지도 동일 규칙으로 재생 경로 `wacz/<학기>/<파일>`을 계산하므로, 수동으로 WACZ를 넣을 때 이 규칙을 지키면 자동으로 연결된다.

## 부록 C. 문제 해결

- **목록에 "manifest.csv를 읽지 못했습니다"** — index.html을 직접 연 경우다. 보기.command로 다시 연다.
- **Archive 버튼을 눌렀는데 재생이 빈 화면** — 해당 WACZ 파일이 `wacz/<학기>/`에 없거나(캡처 전), 파일명이 슬러그 규칙과 안 맞는 경우다. admin.html에서 상태·캡처일을 확인한다.
- **캡처.command가 "캡처 도구가 없습니다"** — 6장 설치를 안 한 Mac이다. 두 줄을 실행한다.
- **시트를 못 읽어 기존 manifest.csv로 진행** — 오프라인이거나 시트 공유가 막힌 경우다. 인터넷/시트 공유(링크가 있는 모든 사용자-뷰어)를 확인한다. 이 경우에도 캡처는 기존 CSV로 계속된다.
